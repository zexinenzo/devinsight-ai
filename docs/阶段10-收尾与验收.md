# 阶段 10：收尾与验收

> 2026-11-23。这份文档回答一个问题：**这个系统现在能做什么、不能做什么、为什么停在这里。**

## 1. 一句话

从多个来源采集科技内容，抽成「实体 — 谓词 — 宾语 — 日期」的结构化事实，
按主题查时间线；每条事实带原文证据、日期档位和撤回状态。

## 2. 链路

```
采集（RSS / API / 网页）
  └─ 正文补全 enrich      抓不到全文的源留摘要，不阻塞
       └─ 事实抽取        谓词闭集 + 宾语形状 + 自反 / 超长 / 字段校验
            └─ 落库        uq_fact_claims_identity 保证幂等，重跑不产生重复行
                 └─ 时间线  timeline / asof，支持「这天之后才成立」
                      └─ 撤回  retracted_at + retracted_replaced_by
```

三条命令覆盖全部日常操作：

```bash
make test                                              # 442 passed
.venv/bin/python scripts/extract_facts.py --limit 20 --min-body-chars 300 --dry-run
.venv/bin/python -m app.cli timeline 英伟达              # 在 apps/api 下执行
```

## 3. 数据快照（2026-11-23 实测，非估算）

| 指标 | 数值 | 口径 |
|---|---|---|
| 测试 | 442 passed | 含 5 个正文门槛测试、3 个 enrich 窗口测试 |
| 文档总量 | 1917 篇 | 2026-11-21 统计，多源 |
| 本文抽取出的事实 | 4 条 / 20 篇 | 正文级抽样，3 条 `stated` |
| 摘要级抽样 | 52 条 / 20 篇 | 其中 50 条日期为 `published` 兜底 |
| 正文补全 | 26 篇 | 两轮 enrich，成功率 7/10、19/20 |
| 误标记回滚 | 77 篇 | 「无正文却已判定」，重置后可重抽 |
| 撤回记录 | 11 条 | 其中 4 条有 `replaced_by` |

**`stated` 占比是这份表里最该看的一行**：摘要级 4%，正文级 75%。
它直接决定时间线可不可信——用发文日期冒充事件日期，等于把「2 月成立的公司」
记到 11 月，误差九个月。

## 4. 一个对照实验：正文到底有没有用

同一套提示词、同一个模型、同样的 20 篇上限，只改候选集的正文门槛：

| | 摘要级（`--min-body-chars 0`） | 正文级（`--min-body-chars 300`） |
|---|---|---|
| 抽出事实 | 52 条 | 4 条 |
| `published` 兜底 | 50 条（96%） | 1 条（25%） |
| 「无可抽事实」 | 12 篇 | 17 篇 |
| 典型错误 | `微软研究院 --released--> Lean 语言`（Lean 是 2013 年的） | 无 |

结论有两条，方向相反，必须一起说：

1. **正文让日期可信**：`stated` 从 4% 升到 75%。
2. **正文不等于事实更多**：候选换成 Hacker News 的 Ask HN、博客、论文之后，
   事实数从 52 掉到 4——这些文本是观点和技术讨论，本来就没有「某公司发布某产品」。
   17 篇判「无可抽事实」是正确判断，不是模型偷懒。

所以「事实密度」不能当质量指标。**摘要级 52 条里有相当一部分是汇编文的假事实，
正文级 4 条里没有。**

## 5. 五条已知限制

### 5.1 只有摘要的源，日期只能靠发文时间兜底

- **现象**：最新 20 篇里 19 篇 `content_text IS NULL`，摘要 35~328 字。
- **成因**：源站只提供摘要（或付费墙 / 需要 JS 渲染），`enrich` 抓不到全文。
- **状态**：**外部约束**。两轮 enrich 后，可补正文的候选只剩 20 篇。
  其余未补上的原因尚待核实——`content_status` 可能是 `empty`（源站本无全文），
  也可能是 `failed`（重试次数用尽）。两者都意味着「再跑 enrich 也不会变」。
- **后果**：这类事实的 `valid_from` 是发文日期，不是事件日期。

### 5.2 汇编文（周刊）会制造假同日事件簇

- **现象**：《科技爱好者周刊》一篇抽出 7 条：特斯拉 Cyberbot、戴森牙刷、
  哈佛 AI 手杖、微软 Lean……全部落在同一个出版日。
- **成因**：周刊是二手汇编，几十条互不相关的事件共用出版日，正文里没有精确日期。
- **识别信号**：单篇事实数 ≥8、主语去重数 ≥5、`published` 兜底占比 ≥80%，
  三个同时成立几乎一定是汇编文。**三个信号已明确，尚未实现，也未接入选取流程**（见待办）。

### 5.3 `retracted_replaced_by` 只修宾语错误，修不了谓词错误

- **实测**：`funded` 的 4 条撤回里 3 条能接替，`open_sourced` 1/3，`founded` 0/4。
- **原因**：接替是「同一个主语、同一个谓词、换宾语」。谓词本身错了（把「入选指数」
  写成 `funded`），接替表里没有对应的行可挂。
- **后果**：谓词错误的撤回是终态，只能重新抽取。

### 5.4 撤回不释放唯一槽位

- `uq_fact_claims_identity(subject_id, predicate, object_text, document_id)`
  没有 `WHERE retracted_at IS NULL`。
- **好处**：同一篇文档里，错误的宾语被撤回后不会再被录进来，重跑不会复活错误。
- **代价**：撤回错了无法在同一篇文档内恢复，只能换文档或改约束。

### 5.5 向量索引不可用

- `vector_index_unavailable`：`~/.cache/devinsight/models/intfloat__multilingual-e5-small`
  缺 `model.onnx` 与 `tokenizer.json`。
- **影响范围**：只影响语义检索，不影响事实抽取与时间线。
- **状态**：待办，不影响验收。

## 6. 为什么停在这里

继续投入有三个方向，边际收益都在衰减：

| 方向 | 需要做什么 | 收益 |
|---|---|---|
| 补齐正文 | 换源、上无头浏览器 | 语料结构问题，工作量在数据不在代码 |
| 提高抽取密度 | 改提示词、换模型 | 事实数量上去了，日期准确率会掉回来 |
| 汇编检测接入 | 20 行代码 | 能挡掉假同日簇，但只覆盖一种源 |

而**当前状态已经能支撑完整的演示与讲解**：采集 → 抽取 → 校验 → 时间线 → 撤回，
每一环都有测试、有设计文档、有真实数据跑过。

## 7. 面试可讲的五个技术点

### 7.1 「谓词合法」不等于「宾语合法」

`funded` 把投资方填进宾语，谓词名完全合法，词表校验一条都拦不住。
所以校验分两层：先查谓词名在不在闭集，再按该谓词的 `object_type` 查宾语形状。
**校验的粒度要跟错误的粒度对齐**，笼统地「校验一下」等于没校验。

### 7.2 日期必须分档，不能只有一列 `valid_from`

`stated`（文中明说）/ `published`（发文时间兜底）/ `unknown` 三档存进
`valid_from_source`。混成一列之后，你永远不知道时间线上某个点是真的还是猜的。
一篇 2026 年的回顾文章提到「2024 年发布 GPT-4o」，兜底就把它挪到 2026 年。

### 7.3 「没有记录」不等于「不是这样」

`as_of` 查一个早于所有事实的日期，返回空。但空有两种成因：
「那天确实没有这条事实」和「所有事的起点都晚于那一天」。
前者是结论，后者是没查到。所以空结果必须回报「N 条起点晚于该日」，
否则用户会把缺数据读成否定结论。

### 7.4 「模型说了空数组」和「模型说的话解析不出来」必须分开

`[]` 是「本文没有可抽事实」，`None` 是「输出不是合法 JSON」。
合并成 `[]` 之后，一批文档抽不出东西时，你分不清是语料没料还是模型没干活——
而这两种情况要采取的动作完全相反（换源 vs 换模型）。

### 7.5 状态要记在文档上，不能靠事实行反推

「抽过没有」最早靠 `fact_claims` 有没有行来判断，于是 342 篇无事实文档每轮都被重判。
改成 `documents.facts_extracted_at` 之后又出现新问题：它写在「无事实」判断**之前**，
导致只有摘要的文档被永久标记，补了正文也不会重抽——77 篇中招，靠
`--reset-no-body` 退回队列。

**任何「已处理」标记都要问一句：处理失败时它会不会被误写。**
