# 阶段 9：抽取期宾语形状校验

> 目标只有一个：让「宾语根本不是这个谓词该有的东西」这类错误**写不进去**。
> 不改表结构，不加迁移，不回补历史。

## 1. 为什么放在抽取入口，而不是修复档

`scripts/repair_facts.py` 的模块文档早就写了这条结论：泛称宾语的正确处理是**在抽取期用
`object_type` 挡掉，不为它回补历史**；`benchmark` 谓词整条不进任何档。

按这条结论，把它加进修复档等于给一个已经正确的决定再实现一遍，而且会让「`benchmark`
整条不进」的排除失效。所以这一步只动一处：`to_fact` 的校验链。

## 2. 判据只有一份

`apps/api/app/services/predicate_specs.py` 末尾：

```
def object_shape_problem(predicate: str, object_text: str) -> str | None:
```

它按 `PredicateSpec.object_type` 选规则，**不看谓词名**。`fact_extraction.to_fact`
在长度校验之后调它一次，命中就返回原因码，和 `too_long`、`malformed` 同级。

`PredicateSpec` 那次「两张表漏一个谓词」的教训是：同一件事写两遍，早晚漏一遍。
所以这里没有第二份规则表。

## 3. 拦什么

| object_type | 规则 | 原因码 | 真实样本（取自基线） |
|---|---|---|---|
| `product` / `benchmark` | 数量短语 | `object_is_quantity_phrase` | `30 个库`、`7 款新模型`、`18 public datasets` |
| `benchmark` | 泛称榜单或评审团 | `object_is_generic_ranking` | `leaderboard`、`LLM judges panel`、`榜单` |

判据全落在宾语自身的形状上，不需要读原文——这是它能放在抽取入口的前提。凡是要看原文
才能判的（比如「这个宾语是不是主语自己」），不属于这一步。

## 4. 为什么量词是必需的

数量规则要求「数字 + 量词 + 少量汉字」。量词不能省，这是整个规则里最容易写错的地方：

| 宾语 | 省掉量词会怎样 | 实际是什么 |
|---|---|---|
| `20 周年纪念版` | 被误判成数量 | 正常产品名 |
| `2026年` | 被误判成数量 | `founded` 的合法宾语 |

误杀比漏拦更贵：被拦掉的事实不会有第二双眼睛看见，而漏掉一条只是回到今天的样子。

## 5. 不该拦的

`version`、`year_or_org`、`scale`、`amount` 四种类型**整类排除**，它们的宾语本来就该以
数字开头：

```
1.30.7                 版本号
2026                   创立年份
1000 人                裁员规模
2.7亿元回购专项贷款     金额
```

测试里对每一条都钉了用例（`tests/test_object_shapes.py` 的
`test_keeps_legitimate_objects`），因为这几条是唯一会被「数字开头」规则误伤的地方。

## 6. 被丢掉的要能看见

`extract_facts.py` 新增 `rejected_object_shape` 计数，逐条打印被丢掉的宾语：

```
[3] x 宾语形状不符（object_is_quantity_phrase）：30 个库
```

只计数不打印的话，日志里「模型这次没抽」和「校验拦掉了」长得一模一样，而这批里恰恰可能
误杀真正的产品名。摘要行也加了 `宾语形状不符 N 条`，比例高时打一句提示。

## 7. 明确不处理的两条

| 样本 | 为什么不做 |
|---|---|
| `Metacritic` / `Metascore` 当 `benchmark` | 评分聚合站，需要知道「这是什么站」，没有形状判据 |
| `Alder Lake` 当被测基准 | CPU 代号是测试平台，需要领域知识 |

硬编码一份这样的词表，就是照着已有样本拟合：下一个 `Geekbench`、`Zen 5` 照样漏，还多了
一份要维护的名单。留在这两条不动，比做一个看起来能用的词表诚实。

## 8. 遗留

库里已有的 `released --> 30 个库` 还在，新规则只管以后写入的行。要清掉需单独撤回一次
（`repair_facts.py retract`），暂不处理——`released` 谓词的宾语约定本身还是模糊的，单清
一行不解决根因。

## 9. 测试

`apps/api/tests/test_object_shapes.py`：18 条。

- 该拦的拦：样本全部取自 `docs/数据品质基线.md` 的真实行，不是编的例子；
- 不该拦的不拦：`1.30.7`、`2026`、`1000 人`、`2.7亿元…`、`20 周年纪念版`；
- 规格表里没有的谓词一律放过（没有声明的类型，就无从判形状）。
